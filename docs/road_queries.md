# Numeric road queries

Three complete original functions recover 2,092 bytes / 523 instructions.
Numeric names and alternate offset-based views describe observed accesses;
they do not identify original classes, an asset format or a format capacity.
The approved source-free evidence proves complete raw/assembly intervals,
terminal return delays, zero alignment padding and all 15 encoded incoming
calls in 11 complete hashed caller intervals. No complete original body was
already registered when this scope was approved.

| Entry | Bytes | Observed behavior |
| --- | ---: | --- |
| `001CC710` | 164 | First flagged provider whose header bounds contain the point; returns its header. |
| `001CE620` | 1,120 | Ordered four-vertex XZ side tests, threshold selection and optional mode output. |
| `001CEA80` | 808 | Grid-cell candidate scan followed by cached neighboring-road queries. |

`001CC710` returns the captured header at provider `+0x10`. It does not validate
the header's nested pointer or its first word. An unsuccessful iteration
reloads the global manager and byte count. The existing keyed lookup
`001CCA28` has its own captured-manager behavior and remains real shared code.

`001CE620` independently narrows index and count to signed 16 bits. A count
of one or less returns the incoming threshold without writing outputs.
Each segment copies two four-vertex quads in the original XYZ load/store
order. Both use the published spatial queries' separate XZ products, strict
`-0.1 < component < 0.1` tiny-edge tests and sticky side value after a skipped
edge. A positive side ends the edge loop; the candidate gate remains the
independent strict comparison against the incoming threshold.

A null mode pointer skips the second quad. Otherwise its final ordered side
comparison becomes a full 32-bit mode store, followed by the byte vertex
store. Aliased outputs therefore retain the original partial overwrite order.
Unsuccessful queries leave both outputs untouched. The caller's mode slot is
never fabricated or initialized by this implementation.

`001CEA80` multiplies radius by itself before its first provider call. It
uses the real GNU `ceilf` and float-to-unsigned conversion for the captured
relative point and header width. The conversion clamps negative values to
zero and saturates large positive values according to its unchanged source;
it is not replaced by a C cast. A registry result indexes byte-addressed cell
storage. Lazy initialization captures the old count before publishing the
first pointer, setting the flag byte and publishing the secondary pointer.
The first halfword lookup supplies a **byte offset** for the second halfword
load. Returned candidate pointers use the unsigned record number, while the
lower query receives its signed 16-bit interpretation.

The cell loop reloads its count and lookup pointer after each query. A found
cell publishes the road pointer even when it has zero candidates and the
function ultimately returns null. The fallback retains the masked-key cache,
including failed lookups, and reloads the neighbor array and count at the
observed points. Successful candidate output stores preserve captured road
and record pointers and subsequent fresh reads.

## Reuse

Production calls the published provider, inclusive bounds and numeric-key
registry APIs, with the existing road/vector layouts and compiler annotation.
The native runner compiles the new functions and unchanged provider, bounds,
registry and their source closure as separate translation units. Every helper
used by these selected functions executes real C. Unused allocator and trig
hooks fail if reached. No library-call observer or fabricated helper output is
used by the original instruction tracer.

Native runtime objects compile the unchanged Sun/newlib `ceilf.c` and GNU
`fp_bit.c`. The original notices remain in those files and the existing newlib,
GNU exception and GPL license files. The GNU object uses the authentic
`FLOAT`, `US_SOFTWARE_GOFAST`, `NO_DENORMALS`, fine-grained unpack/conversion
defines and explicit little-endian bit-order setting. Source aliases only
bind the real exported routines to their numeric entry names. These already
published helper bodies receive no new reconstruction or matching award.

## Validation and limits

Nine genuine whole-function links cover GCC 3.2.3, GCC 2.9 and its supported
optional SAVE128 attribute. Every link resolves completely; none matches all
retail bytes, so all three functions remain reconstructed. Complete natural
sizes and bytes are retained, without cropping, instruction masks, patches,
assembly or intrinsics. The transparent `always_inline` directive on newer
GCC expresses the complete copied-quad arithmetic in each original body; it
does not establish the original syntax or compiler identity.

Both actual target compilers independently prove 23 layout words, the six-GPR
plus `f12` lower call and four-GPR plus `f12` upper call, including their actual
delay instructions. Fifteen successful real `-M` invocations pin 52 distinct
source/header dependencies across target and native builds. The selected
originals contain 45 local branches, 62 stores including saved registers and
delay slots, ten helper calls and three returns. All immediate float sites
agree with the source's exact binary32 literals.

The 427 synthetic fixtures execute 171,784 original instructions, at most
1,673 per invocation. They reach all 515 selected non-`BREAK` instructions;
the remaining eight instructions are original compiler division traps.
The warning-free 32-bit native executable passes 6,132,301 checks, including
returns and complete initialized memory windows, ties and threshold gates,
negative coordinates, lazy cells, byte-offset lookup, failed-cache reuse,
unsigned-pointer/signed-index divergence and aliased output stores. The large
check count includes memory-preservation assertions and does not represent
that many distinct fixtures or original paths.

Nine guard methods test bounded complete entries, initialized aligned memory,
actual return/delay encodings, signed/unsigned division traps, raw float-bit
transfers and the meaningful output/lookup invariants. Four original-dependent
methods explicitly skip when the exact local ELF is absent; a separate absent-
file replay passes five synthetic methods and skips those four without moving
or deleting the user's file. Original conversion checks cover finite raw-bit
classification and shifts. Native-only NaN/infinity conversion assertions
test the authentic GNU source; the instruction observer still rejects
nonfinite FP stores and makes no corresponding EE arithmetic claim.

Numerical observation uses separately rounded host binary32 values for finite
normal/zero arithmetic. It does not prove EE FCR flags, exceptional/subnormal
arithmetic, extended precision, timing, memory-fault behavior or identical
caller-stack placement. Raw-bit subnormal classification tests do not perform
subnormal arithmetic. Fixtures use initialized synthetic records and trusted
output pointers; no asset capacity, ownership, arbitrary invalid-pointer
behavior or complete indirect control-flow graph is established. Production
adds no null-output, record-capacity or polygon-validity guards.

The author read all 523 selected instructions, all six complete supporting
originals and active helper source paths, all 15 bounded incoming argument/
return windows, and the complete short caller `001D1650`. Other large callers
receive complete byte/assembly identities and bounded call-context review,
not a claimed complete semantic read. The parent read the complete initial
selected originals and C/header; independent final peer and parent packet
reproduction passed. All three functions are registered. Their nine complete
canonical-only comparison dictionaries are unchanged, with no exact-code
award. The isolated historical packet preserves the author review stage.

## Reproduce

After supplying the supported original ELF and the repository's compiler
dependencies, run from the repository root:

```powershell
python tools/trace_road_queries.py
python tests/native/run_road_queries.py
python -m unittest discover -s tests -p test_trace_road_queries.py
```

The public golden header contains only authored synthetic inputs and expected
observations. Original instructions, disassembly, private proof commands and
proprietary assets remain outside the published source.
